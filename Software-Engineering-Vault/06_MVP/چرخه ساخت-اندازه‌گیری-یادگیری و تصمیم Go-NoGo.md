# چرخه ساخت-اندازه‌گیری-یادگیری و تصمیم Go / No-Go

![[fig_4_2_bml_gonogo.png]]
*شکل تکمیلی ۶-۲: چرخه بازخورد Build–Measure–Learn و دروازه تصمیم‌گیری مدیریتی Go / No-Go (بخش ۴-۶ پرسمن)*

## چرخه بازخورد MVP (`Build – Measure – Learn`)
1. **ساخت (Build):** پیاده‌سازی سریع هسته اصلی محصول (MVP).
2. **اندازه‌گیری (Measure):** جمع‌آوری داده‌های واقعی از نحوه تعامل و رضایت کاربران اولیه.
3. **یادگیری (Learn):** تحلیل بازخوردها برای اعتبارسنجی فرضیات کسب‌وکار.

## تصمیم‌گیری مدیریتی `Go / No-Go` (بخش 4.6 کتاب پرسمن)
مطابق نمودار [[حداقل محصول پذیرفتنی (MVP)]]، پس از ارزیابی بازخوردهای دریافتی، تیم و مدیریت تصمیم می‌گیرند:
- **تصمیم Go (ادامه توسعه):** اگر بازخورد کاربران مثبت باشد و نیاز بازار تأیید شود، محدوده نمونه بعدی تعریف شده و قابلیت‌های جدید به صورت افزایشی توسعه می‌یابند.
- **تصمیم No-Go / Pivot (توقف یا تغییر مسیر):** اگر فرضیات اولیه نادرست از آب دربیایند، پیش از هدررفت سرمایه کلان، پروژه متوقف یا مسیر محصول اصلاح (`Pivot`) می‌شود.

---

## 🔬 شش گام عملیاتی چرخه یادگیری معتبر (بخش ۶-۳ جزوه)
برای جلوگیری از یادگیری کاذب در چرخه `Build – Measure – Learn`، تیم شش گام زیر را به‌ترتیب اجرا می‌کند:
1. **فرضیه را مشخص کن:** نگارش یک باور پرریسک و قابل آزمون *(مثلاً: دانشجویان برای یافتن برنامه بدون تداخل از برنامه‌ریز خودکار استفاده می‌کنند)*.
2. **آزمایش کمینه را طراحی کن:** انتخاب کوچک‌ترین راه‌حلی که شواهد قابل اتکا تولید کند.
3. **بساز (`Build`):** آماده‌سازی محصول یا آزمایش با کیفیت کافی برای مشاهده رفتار واقعی کاربر.
4. **اندازه‌گیری کن (`Measure`):** جمع‌آوری شاخص‌های مرتبط مستقیم با فرضیه *(به‌جای شاخص‌های نمایشی مانند صرفاً تعداد بازدید یا دانلود)*.
5. **یاد بگیر (`Learn`):** مقایسه نتایج واقعی با معیار موفقیت از پیش تعیین‌شده.
6. **تصمیم بگیر (`Persevere / Pivot / Stop`):** ادامه و بهبود مسیر فعلی (**`Persevere`** / معادل `Go`)، تغییر فرضیه یا جهت محصول (**`Pivot`**) یا توقف سرمایه‌گذاری (**`No-Go / Stop`**).
